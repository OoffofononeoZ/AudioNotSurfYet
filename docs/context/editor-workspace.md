# Editor 工作区框架

owner 于 2026-10-16 要求实施“Editor 页面框架与控件改版”计划，并按三阶段验证后分别本地提交。本次统一公共框架，不改变标记、波形/BPM、分离、自动标记和叠加图表内部算法；工程仍为 JSON V1，不扩大正式 readiness 或发布授权。

## 顶栏与播放

- 统一深色平面顶栏：桌面 64px，细底线。左侧导入／导出使用 34px 点击区和 20px 线性 SVG，格式通过提示标明 JSON V1。
- 中部为标记编辑、音轨分离、自动标记页签；支持方向键、Home、End 与 roving tabindex。可用内容宽度小于 800px 时移到第二行。窄屏两侧为导航和 Settings 留位。
- 右侧依次为新工程／保存中／已保存／未保存、叠加层开关和特征选择，最右侧沿用共享 Settings。完整工程错误保留在顶栏下方提示区。
- MusicBar 常驻，统一管理歌曲信息、播放、seek、音量与队列；Editor 不再重复歌曲名、艺人、播放时间或通用播放按钮。工作区租约继续强制单曲循环、锁定模式切换，离页恢复用户偏好。
- 时间轴平移、缩放和重置使用图标，保留 aria-label 和 title；标记新增及区间操作保留文字。

## 叠加层与草稿保护

`EditorAnalysisOverlay` 继续拥有开关、菜单和图表，控制区 Teleport 到顶栏右侧槽位，仅在标记编辑可用。菜单向下且右对齐，首次未选特征时开关打开原有菜单；焦点返回、三手柄、窗口级图表与指针穿透行为保持原合同。

换歌与队列保护见[应用外壳契约](app-shell.md#播放模式)。导航编排在 `useEditorTrackNavigation`；一次性目标／工程修订批准在 `EditorTrackChangeApproval`；控制器仍是工程保存与入口冲突检查的事实源。现有控制器和大编辑组件保留领域职责，本次只提取新增的顶栏、图标和导航编排，不按规模提示批量重构内部编辑逻辑。

## 本次验证

第一阶段：类型检查、35 项播放／会话／处理生命周期测试及 Chrome 两项换歌保护回归通过，覆盖保存失败、取消、明确覆盖、导出、刷新、当前项删除和清空。

第二阶段：Chrome 三项框架回归及七项叠加层集成测试通过，覆盖页签键盘、菜单方向、首次选择、焦点和三个手柄入口。真实浏览器完整布局及编辑回归在第三阶段收口；这些结果不作为历史 canonical 或正式 readiness。
