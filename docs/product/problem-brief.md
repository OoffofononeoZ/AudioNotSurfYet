# Problem Brief

## Summary

AudioNotSurfYet 已完成面向音频分析学习者的 Analyzer 候选，并以 `Ready with waivers` 进入有条件就绪。Analyzer 解决的核心问题不是“拿不到 Meyda 结果”，而是已有文档、示例和控制台工作方式通常只呈现数值或数组，学习者难以把结果对应到歌曲中的具体时刻、当时的听感，以及音色为何发生变化。

Editor E0 解决下一层问题：用户能够听出歌曲中存在音符、音色或效果，却缺少一个与歌曲时间轴、节拍和分析特征对齐的工具，把这些观察反向整理成可保存的数据。Editor 因此定位为“逆向制曲”标注工具，而不是修改声音的音频编辑器。

## Target User

- Analyzer 用户：正在学习音频分析、Meyda 或音频可视化，希望建立“数值—声音—时间”联系的学习者。
- Editor E0 目标用户：希望拆解已有歌曲的学习者或制作者，需要反向记录音符、短音色、长音色或效果出现的时间，而不是创作或修改原始音频。
- Editor 核心任务：选择一首本地歌曲，在循环试听中建立节拍时间轴，按内部分类创建点事件和范围事件，用一个分析特征辅助判断，并把工程保存后恢复或交换。
- 当前 owner：`project-owner`，负责产品、技术和阶段批准，并亲自执行学习结果验证。

首版不以专业母带工程师、实时演出操作者或需要完整 DAW、多轨制作、录音、混音或云协作的用户为主要用户。

## Current Pain

- Meyda 的标量、向量和结构化输出形态不一致，孤立数字或数组难以形成直觉。
- 文档或控制台工作方式缺少与歌曲播放位置同步的连续上下文；学习者需要手工记时间、反复切换工具或凭耳朵猜测。
- 当前仓库已有本地音频队列、播放控制和零散分析/可视化能力，但它们尚未形成一个围绕学习任务的统一交互。
- 不同特征不能在同一时间视窗内直接比较，导致学习者难以判断多种描述是否指向同一段声音变化。
- 通用文本或表格不能让用户在节拍网格上快速记录大量音符、音色和效果事件，也不能随缩放自动调整可点击精度。
- 普通音频播放器不能保存“某个分类在何时出现、持续多久”的结构化工程；手工记秒数难以复核、调整或与分析图对齐。
- 完整编曲软件的目标是生成或修改音乐，功能和交互远超当前逆向听辨任务，不能直接替代轻量标注工作区。

## Desired Outcome

### Analyzer outcome（approved）

学习者能够在同一 Analyzer 工作区中：

1. 加载并播放本地音频；
2. 最多选择四个不重复的 Meyda 特征；
3. 在共享视窗、缩放和游标下观察同一时间段；
4. 点击图表跳转到对应声音；
5. 读取固定分析参数和游标处的精确值；
6. 用首批 RMS、Amplitude Spectrum、Chroma 正确解释预设片段中的数值与听感关系。

长期结果是以纵向切片覆盖 `src/data/analyzerData.ts` 中全部 21 个特征，而不是一次性展示一个不可验证的全功能仪表盘。

### Editor E0 outcome（approved）

用户能够在同一首歌曲的循环播放中：

1. 从 Header 的当前歌曲或播放列表中的指定歌曲进入 Editor；
2. 通过波形、共享视口和 tempo map 找到需要标记的位置；
3. 按 lane 与 inner class 创建短音色/音符的点事件；
4. 以起点和终点创建长音色/效果的范围事件，并调整或删除；
5. 选择一个现有 Meyda 特征作为与标记区域精确对齐的半透明辅助层；
6. 将点事件、范围事件、节拍与工作区状态保存为本地版本化工程，并在刷新或重新进入同一歌曲时恢复。

Editor 的输出是绑定单首歌曲的时间数据集；它不会修改、重新编码或导出新的音频。

## Why Now

- 仓库已具备本地文件选择、队列、Web Audio 播放和可视化基础，可以复用为分析时间轴的输入与时钟。
- Analyzer 已有特征目录和试验性表达，产品方向已经足够明确，可以停止从导航和代码猜测意图。
- 如果继续让播放器、状态和分析各自演进，后续会出现多个 AudioContext、不同步游标、重复缓存和无法验证的特征实现。
- Analyzer 已提供单 AudioEngine、共享时间轴、21 项分析能力和双浏览器证据，Editor 可以在不复制播放与分析基础设施的前提下建立逆向标注体验。
- 在开始 Editor 代码前先批准产品意图，可以避免从现有 `/comingsoon` 占位、音乐列表加号或聊天示例反推未经确认的工程格式和交互。

## Constraints

- 音频、元数据和分析结果在当前范围内只在浏览器本地处理。
- 输入限用户选择的 MP3、WAV、FLAC，单首目标上限约 15 分钟。
- 首发浏览器为最新稳定版 Chrome 和 Edge 桌面端，目标视口宽度为 1024、1280、1920 CSS px。
- 静态 SPA 运行在 HTTPS 或 localhost；托管平台留到 release 阶段决定。
- 全曲分析不得阻塞主线程；播放游标以 AudioContext 时钟为准。
- 当前交付使用阶段门禁，不承诺未经估算的日历日期。
- Editor 首版继续使用浏览器本地数据边界，首个工程格式只提供版本化 JSON；新增文件格式或第三方 BPM 依赖必须另获 owner 批准。
- 点事件和范围事件都以节拍网格为主要定位方式；范围事件必须具有严格晚于起点的终点。
- Editor 产品意图获批前不进入系统设计、实现或依赖安装。

## Risks

- 15 分钟频谱或结构化特征若保存原始高频帧，可能造成内存、存储和渲染压力。
- 文件句柄权限不保证跨会话持续；恢复体验必须允许缺失权限和文件移动。
- 不同格式解码、采样率和浮点实现可能让黄金结果出现可接受但非零的误差。
- Editor 新路由、草稿、右键交互、范围事件和叠加层会扩大资源、持久化、键盘与双浏览器验证面；Analyzer 的 readiness 不能替代 Editor 自身证据。
- 仅由 owner 验证学习结果能够快速形成证据，但不能代表更广泛用户群体。
- 同一分类的范围事件若允许无约束重叠会产生难以解释的数据；E0 已确定同一 lane、同一 inner class 禁止范围重叠，不同分类仍可同时存在。
