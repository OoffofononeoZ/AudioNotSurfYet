# Problem Brief

## Summary

AudioNotSurfYet 面向希望学习音频分析的人。核心问题不是“拿不到 Meyda 结果”，而是已有文档、示例和控制台工作方式通常只呈现数值或数组，学习者难以把结果对应到歌曲中的具体时刻、当时的听感，以及音色为何发生变化。

本项目要把本地音频播放、共享时间轴和特征解释整合为一个可操作的分析体验：用户一边听，一边比较特征随时间的变化，并从图表跳回对应声音。播放器、队列和共享时间轴是分析体验的基础设施，不是独立的产品终点。

## Target User

- 主要用户：正在学习音频分析、Meyda 或音频可视化，希望建立“数值—声音—时间”联系的学习者。
- 核心任务：加载一首本地歌曲，选择要观察的特征，在播放、暂停和跳转时比较多个特征，并解释数值变化与听感、音色之间的关系。
- 当前 owner：`project-owner`，负责产品、技术和阶段批准，并亲自执行学习结果验证。

首版不以专业母带工程师、实时演出操作者或音频编辑人员为主要用户。

## Current Pain

- Meyda 的标量、向量和结构化输出形态不一致，孤立数字或数组难以形成直觉。
- 文档或控制台工作方式缺少与歌曲播放位置同步的连续上下文；学习者需要手工记时间、反复切换工具或凭耳朵猜测。
- 当前仓库已有本地音频队列、播放控制和零散分析/可视化能力，但它们尚未形成一个围绕学习任务的统一交互。
- 不同特征不能在同一时间视窗内直接比较，导致学习者难以判断多种描述是否指向同一段声音变化。

## Desired Outcome

学习者能够在同一 Analyzer 工作区中：

1. 加载并播放本地音频；
2. 最多选择四个不重复的 Meyda 特征；
3. 在共享视窗、缩放和游标下观察同一时间段；
4. 点击图表跳转到对应声音；
5. 读取固定分析参数和游标处的精确值；
6. 用首批 RMS、Amplitude Spectrum、Chroma 正确解释预设片段中的数值与听感关系。

长期结果是以纵向切片覆盖 `src/data/analyzerData.ts` 中全部 21 个特征，而不是一次性展示一个不可验证的全功能仪表盘。

## Why Now

- 仓库已具备本地文件选择、队列、Web Audio 播放和可视化基础，可以复用为分析时间轴的输入与时钟。
- Analyzer 已有特征目录和试验性表达，产品方向已经足够明确，可以停止从导航和代码猜测意图。
- 如果继续让播放器、状态和分析各自演进，后续会出现多个 AudioContext、不同步游标、重复缓存和无法验证的特征实现。

## Constraints

- 音频、元数据和分析结果在当前范围内只在浏览器本地处理。
- 输入限用户选择的 MP3、WAV、FLAC，单首目标上限约 15 分钟。
- 首发浏览器为最新稳定版 Chrome 和 Edge 桌面端，目标视口宽度为 1024、1280、1920 CSS px。
- 静态 SPA 运行在 HTTPS 或 localhost；托管平台留到 release 阶段决定。
- 全曲分析不得阻塞主线程；播放游标以 AudioContext 时钟为准。
- 当前交付使用阶段门禁，不承诺未经估算的日历日期。

## Risks

- 15 分钟频谱或结构化特征若保存原始高频帧，可能造成内存、存储和渲染压力。
- 文件句柄权限不保证跨会话持续；恢复体验必须允许缺失权限和文件移动。
- 不同格式解码、采样率和浮点实现可能让黄金结果出现可接受但非零的误差。
- 当前环境尚未发现 Edge 安装；缺少真实 Edge 证据时不得宣称双浏览器验收完成。
- 仅由 owner 验证学习结果能够快速形成证据，但不能代表更广泛用户群体。
