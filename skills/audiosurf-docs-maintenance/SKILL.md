# 文档维护

先用标题、关键词和引用定位本次相关文档，不默认加载全部目录。根 AGENTS.md 保存持续有效的用户约束和工作规则，README 提供运行入口；专题说明保留本地设计原因、契约、状态和证据。已有阶段目录可继续使用，不为普通任务新建全套文件或空目录。

| 内容 | 处理 |
| --- | --- |
| 当前契约、设计原因、实际限制 | 保留；过长时拆专题并更新父级入口 |
| 未解决问题、验收阈值和必要运行证据 | 保留或迁移，不能因旧或长而删除 |
| 重复且已闭环的过程、失效排查 | 确认实现和引用后按任务压缩或清理，历史由 Git 查回 |
| 仍有预防价值的经验 | 压缩成原因、当前规则及验证依据 |
| 正式 canonical 身份、原始资料、fixture/golden 和大型本地产物 | 保持相应证据/许可边界，不当作冗余日志删除 |

本轮迁移不授权批量删除历史文档。后续整理限于任务相关内容；无法判定当前作用时保留关键结论并注明待核实。禁止进入 `trash/`，不默认另建 archive/changelog 存放删去的过程。

手写 Markdown（含 AGENTS.md、README、SKILL.md）统一建议不超过 500 行；501–799 行由 `repo:check` / `test:docs` 提示，800 行及以上阻断并禁止提交。完整文件计数包含标题、frontmatter、代码块、注释与空行；LF/CRLF 等价，末尾换行不多算一行。自动生成的代码地图不受手写文档规模限制，仍校验引用和生成一致性。

超限时精简的是文字：合并重复解释、删去已核实无独立价值的冗余、改写啰嗦表达，同时保留正常段落、标题、列表和代码排版。不得靠长单行、合并无关段落、减少必要换行或截断正文来过门禁，也不把拆文件当作逃避文字精简的办法；确有独立主题时仍可拆 references 或专题并同步导航，地图只由工具维护。

精简前核对关键契约、接口字段、设计原因、未解决问题、阈值、失败事实、批准边界、canonical/run/commit 身份、hash、artifact 与许可记录。若可能丢失关键信息，保留原文，汇报文件路径、规模、受影响信息和待核验项，并停止提交；不新增历史文档豁免，不把不确定信息当作冗余删除。检测程序只检查行数，不能证明文字精简无损。

既有 frontmatter 可保留，按内容需要更新；新文档不强制统一字段。行为或接口变化只更新实际受影响的合同、索引和决策；重大取舍先由用户确认，不把推测写成批准。规则冲突先核实，再写明替代关系。

完成后核对相对链接、父级导航、命令与事实，运行 `npm run test:docs` 和交付检查；无需应用构建。
